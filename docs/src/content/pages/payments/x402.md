# x402 integration

AI Agent Bank ships a **simplified, self-labelled x402-style** payment flow for
autonomous commerce. It mirrors the *shape* of the real [x402](https://docs.x402.org)
protocol — request → "payment required" → pay → retry with proof → response — but
it is **not wire-compatible** with the standard, and the code says so explicitly.

> [!WARNING]
> The `x402_note` field returned by the API and this paragraph are intentionally
> explicit: this demo must never be presented as a compliant x402 client or
> server.

## The shape

```
HTTP request to a service
  → 402-ish "payment_required" (+ payment_info: amount, currency, recipient, category, endpoint)
  → Agent Bank evaluates policy + executes USDC payment
  → retry the request with proof (tx_hash)
  → service returns its result
```

Endpoint by endpoint:

| Step | Endpoint | Response |
|---|---|---|
| Discover & request | `POST /services/{id}/request` | `status: "ok"` (free) or `payment_required` |
| Pay | `POST /services/{id}/payment` | `paid` / `blocked` / `approval_required` / `failed` |
| Call with proof | `POST /services/{id}/result` | result + `proof.verified: true` |

## Where it diverges from real x402

| | Real x402 | This build |
|---|---|---|
| Payment request | literal HTTP `402` status with defined headers | JSON body with `status: "payment_required"` and `http_status_hint: 402` |
| Proof | signed payment proof per spec | a `tx_hash` validated against the ledger |
| Wire format | standardized | demo-only |

`marketplace.py` documents this in its module docstring, and every `request`
response carries an `x402_note` repeating the "not wire-compatible" disclaimer.

## Why it exists

It demonstrates the *product idea* of autonomous commerce — an agent hitting a
paywall, the bank paying within policy, and the API returning data — without
fabricating protocol compliance. The real agent→bank→policy→USDC path is what's
honest; the directory and its endpoints are the scaffold around it.
